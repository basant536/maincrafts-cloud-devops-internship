# Task-03: CI/CD Automation for Dockerized Application

## 📌 Project Overview

This project demonstrates a basic CI/CD pipeline for a Dockerized web application using GitHub Actions and Docker Hub.

The application is containerized using Docker and the GitHub Actions workflow automatically builds the Docker image and pushes it to Docker Hub whenever changes are pushed to the main branch.

---

## 🎯 Objective

The main objective of this project is to understand and implement:

- CI/CD automation
- GitHub Actions workflows
- Docker image creation
- Automated Docker image push to Docker Hub
- GitHub Secrets for secure authentication
- Pipeline monitoring and execution
- Docker image validation

🐳 Dockerfile
The Dockerfile is used to create a Docker image for the web application.
It defines the base image, application files and the port used by the application.

🔄 CI/CD Workflow
The GitHub Actions workflow performs the following steps:
Developer pushes code to the main branch.
GitHub Actions workflow is triggered automatically.
GitHub checks out the repository.
Docker Buildx is configured.
Docker Hub authentication is performed using GitHub Secrets.
Docker image is built.
Docker image is pushed automatically to Docker Hub.
The workflow status and logs can be monitored from GitHub Actions.

🔐 GitHub Secrets
Docker Hub credentials are not stored directly inside the workflow.
GitHub Secrets are used for secure authentication.
The following secrets were configured:
DockerHun_basant536
DockerHun_Token
The Docker Hub token is stored securely as a GitHub Secret and is not exposed in the workflow.

📦 Docker Hub
The Docker image generated by the CI/CD pipeline is pushed to the following Docker Hub repository:
Docker Hub Repository:
basant222006/cloud-deployment-hub
The repository contains the Docker image with the latest tag.

⚙️ GitHub Actions
The workflow file is:
.github/workflows/docker-ci.yml
The workflow is configured to run when code is pushed to the main branch.
